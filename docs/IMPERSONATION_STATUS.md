# Synthetic Platform Inspector — Implementation Status

_Generated by surveying the working tree on 2026-05-29 against the original plan._

## Goal recap

Replace the legacy "platform admin impersonates the tenant's highest-role
active user" model (which caused dual-identity UX confusion — banner said
"Vishnu inspecting Acme" while every avatar / "Created by" / chat presence
showed teammate "Vaishak") with a dedicated **synthetic Platform Inspector
user** minted per `(tenant, platform_admin)`:

- `role = 'platform_admin'` → full access by design
- `full_name = "<Inspector Name> (Platform Support)"`
- `org_id / team_id / department_id = NULL`
- `hidden_from_directory = TRUE` so the synthetic user never appears in
  People / Chat / @mention / org-chart / assignable-users lists
- One row per `(tenant, platform_admin)`, reused across sessions

### 12. Platform Audit Logs UI resolves synthetic actors → real inspector

✅ **Done (option a — server-side resolution).**

- **Server:** `server/utils/audit.js` — `annotateInspectorActors()` (line 107)
  batch-fetches `platform_users` from the master DB for any rows whose
  `actor_username` matches `platform_inspector_<id>`, attaching
  `actor_is_inspector`, `actor_inspector_real_name`, and
  `actor_inspector_username` to each log row.
- **Client:** `client/src/pages/admin/AuditLogs.jsx` — `renderActor()` (line 327)
  shows a shield icon + `"(real: <name>)"` annotation for inspector rows.

### 13. Housekeeping job — prune unused synthetic inspector users

✅ **Done.** `server/jobs.js` — `pruneStaleInspectorUsers()` (line 39)
iterates all tenant DBs and deletes synthetic inspector rows with no
audit-log activity in the last 30 days. Scheduled via BullMQ (24 h) with
setInterval fallback.
