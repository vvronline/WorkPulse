# Android Release Signing

How AINO's Android release artifacts get signed with a **production** keystore
instead of the debug keystore Expo generates by default.

---

## 1. Why this exists

Expo's `expo prebuild` generates `android/app/build.gradle` from a template in
which the `release` build type is signed with `signingConfigs.debug`:

```gradle
release {
    // Caution! In production, you need to generate your own keystore file.
    signingConfig signingConfigs.debug
}
```

A debug-signed artifact is fine for sideloading, but the **Play Store rejects
it outright**. It also means every CI build could theoretically use a different
key, which would break app updates.

Wiring a keystore through `android/gradle.properties` **does not work** here:
`android/` is gitignored and regenerated by `expo prebuild` on every CI run,
which overwrites both `build.gradle` and `gradle.properties`. The fix has to run
*during* prebuild — hence the config plugin
[`mobile/scripts/withAndroidSigning.js`](../mobile/scripts/withAndroidSigning.js).
This is the same constraint that `withAndroidGradleMemory` already works around.

---

## 2. How it works

`withAndroidSigning` is registered in `app.config.ts` and, during prebuild:

1. Reads the `ANDROID_KEYSTORE_*` environment variables.
2. Injects a `release { ... }` entry into the `signingConfigs` block.
3. Repoints `buildTypes.release` at `signingConfigs.release`.

| Variable | Required | Meaning |
| --- | --- | --- |
| `ANDROID_KEYSTORE_PATH` | yes | Absolute path, or relative to `mobile/` |
| `ANDROID_KEYSTORE_PASSWORD` | yes | Store password |
| `ANDROID_KEY_ALIAS` | yes | Key alias (`aino-release`) |
| `ANDROID_KEY_PASSWORD` | no | Defaults to the store password |

**When the variables are unset the plugin no-ops** and leaves debug signing in
place, so `npx expo prebuild` and `npx expo run:android` keep working locally
with no credentials. Setting *some but not all* of them throws — a partial
config is always a mistake, and failing loudly beats shipping a debug-signed
release that Play rejects after a full build.

The plugin is idempotent: re-running prebuild will not duplicate the block.

---

## 3. The keystore

Generated with RSA-4096 and 25-year validity (Play requires ≥ 2033):

```
Alias:       aino-release
Algorithm:   4096-bit RSA / SHA384withRSA
Valid until: 2051-07-23
SHA-256:     C4:90:58:2B:F0:4D:EA:A2:CF:55:75:CB:AA:4D:6B:1C:
             40:E9:9A:B5:DF:7B:95:0F:56:45:7C:FF:4A:9B:68:06
```

It lives **outside the repository** at `D:\Learnings\_aino-secrets\` so it can
never be committed by accident. `mobile/.gitignore` also ignores `*.jks`.

> ### ⚠️ Back the keystore up offline, now
> If `aino-release.jks` or its password is lost, the app can **never be updated
> again** on the Play Store — a new key means a new listing and every user has
> to reinstall manually. Store a copy in a password manager or encrypted backup.
> Google's Play App Signing can mitigate this, but only if enrolled at first
> upload.

To regenerate from scratch (only for a brand-new app):

```powershell
keytool -genkeypair -v -keystore aino-release.jks -alias aino-release `
  -keyalg RSA -keysize 4096 -validity 9125
```

## 4. CI configuration

The keystore is passed to GitHub Actions as a **base64-encoded secret** (binary
files cannot be stored directly).

Create the value:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes('aino-release.jks'))
```

Add under *Settings → Secrets and variables → Actions → Secrets*:

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | base64 of `aino-release.jks` |
| `ANDROID_KEYSTORE_PASSWORD` | store password |
| `ANDROID_KEY_ALIAS` | `aino-release` |
| `ANDROID_KEY_PASSWORD` | key password (same as store password) |

The workflow decodes it to a temp path outside the working tree and exports
`ANDROID_KEYSTORE_PATH` before running prebuild.

---

## 5. Local release builds

To produce a release-signed build on a dev machine, export the variables before
prebuild (the plugin reads them at prebuild time, **not** at Gradle time — a
prebuild run without them bakes debug signing into `build.gradle`):

```powershell
$env:ANDROID_KEYSTORE_PATH     = 'D:\Learnings\_aino-secrets\aino-release.jks'
$env:ANDROID_KEYSTORE_PASSWORD = '<store password>'
$env:ANDROID_KEY_ALIAS         = 'aino-release'

cd mobile
npx expo prebuild --platform android --no-install
cd android
./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
```

Output: `mobile/android/app/build/outputs/apk/release/app-release.apk`.
Use `bundleRelease` instead for a Play-format `.aab`.

> Building locally needs ~8 GB of free disk for the Android NDK. A failed NDK
> install can leave an empty `%LOCALAPPDATA%\Android\Sdk\ndk\<version>\` folder
> containing only `.installData`; delete it or Gradle keeps retrying the
> download.

---

## 6. Signature change for existing installs

Android refuses to install an update whose signing certificate differs from the
installed app's. Previously distributed APKs were **debug-signed** (CI) or
**EAS-signed**, so the first release-signed build must be installed after an
**uninstall**. This is a one-time cost and is free to absorb now, before any
Play Store release.

---

## 7. Verifying a build is correctly signed

```powershell
# From the Android SDK build-tools
apksigner verify --print-certs app-release.apk
```

The reported SHA-256 must match the fingerprint in §3. `apksigner` also
confirms the v2/v3 APK Signature Scheme blocks Play requires.
